# District AI for Android

The native Android client for [District AI](https://www.distronode.com), by Distronode. It is
the app submitted to Google Play as `com.distronode.districtai`: calls and transcripts, the
shared inbox, contacts and their intelligence dossiers, multi-party rooms, a self-managed
softphone that places and answers calls through Android's Telecom framework, push
notifications, and workspace settings.

Kotlin, Jetpack Compose and Material 3, on a small set of Gradle modules. Apache-2.0.

The app is a client of the District AI API. Everything it shows comes from that service, and
signing in needs a District AI account. There is no offline mode and no local server.

## Requirements

- **JDK 21.** AGP 9 needs at least JDK 17 to run; 21 is what the build is developed and
  verified on. The modules compile to Java 11 bytecode.
- **Android SDK** with platform `android-37.0` (compileSdk 37) and build tools `37.0.0`.
  `targetSdk` is 36 and `minSdk` is 26. Point the build at the SDK with `ANDROID_HOME` or a
  `local.properties` file containing `sdk.dir=...` (it is gitignored).
- Nothing else. The Gradle wrapper (9.8.0, checksum-pinned) downloads Gradle itself; Android
  Studio is optional.

## Build and test

```sh
./gradlew assembleDebug                      # debug APK: app/build/outputs/apk/debug/
./gradlew testDebugUnitTest                  # every module's unit tests (Robolectric included)
./gradlew detekt lintDebug                   # static analysis and Android Lint
./gradlew :koverLog :koverVerify             # aggregate coverage and its floors
scripts/verify-release-minification.sh       # R8 release build, serializers retained
```

That is also what CI runs, in one job: see [.github/workflows/ci.yml](.github/workflows/ci.yml)
and [CONTRIBUTING.md](CONTRIBUTING.md).

The debug build installs as `com.distronode.districtai.debug`, so it can sit beside a release
install on the same device.

Every configuration is dependency-locked (`<module>/gradle.lockfile`). Changing a version in
`gradle/libs.versions.toml` does nothing until the lockfiles are regenerated; the command is
in the "Regenerating the lockfiles" note in [build.gradle.kts](build.gradle.kts).

## Layout

```
app/                     The application: screens (ui/), navigation, Telecom and calls,
                         push, app links, sign-in, and the wiring in AppContainer.
core/core-model/         API response and request types, and the contract fixture tests.
core/core-network/       The HTTP client over OkHttp, the API interfaces, and the mapping of
                         the API's error envelopes into one result type.
core/core-auth/          Token storage (Android Keystore) and the refresh coordinator.
core/core-data/          Repositories over core-network, and the active-workspace state.
core/core-designsystem/  Colour, type, shape and the primitive composables. Depends on no
                         other module.
core/core-media/         The LiveKit wrapper behind a CallEngine interface.
build-logic/             Convention plugins shared by every module.
contracts/               API contract fixtures generated by the server (see below).
parity/                  A snapshot of the iOS client's endpoint list (see below).
config/detekt/           detekt configuration.
scripts/                 Verification scripts; see scripts/README.md.
.maestro/                A Maestro smoke flow, run locally with scripts/smoke-emulator.sh.
```

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) describes how the modules fit together.

## The contract gate

This repository has no generated API client and the API has no published schema. What stops a
server-side rename from shipping silently is `contracts/`: JSON bodies produced by the
server's own test suite from its real route handlers, committed here, and decoded in
`:core:core-model` (and a few other modules) with a strict decoder that rejects unknown keys.

The gate has two halves, one in each repository:

1. When a response shape changes on the server, the server's suite fails until its fixture is
   regenerated.
2. When the regenerated fixture lands here, the tests here fail until the Kotlin types match.

The fixtures are generated in the server repository, which is private. Refreshing them is a
maintainer task: regenerate them there, copy the changed `*.json` files into `contracts/`
byte for byte, and update the types (and `ContractManifest`'s expected count, if a fixture was
added) in the same commit. Never edit a fixture by hand, and never relax the strict decoder to
make a failure go away; the failure is the signal.

`parity/EndpointID.swift` does the same job against the iOS client: `EndpointParityTest` diffs
it against this client's API interfaces. [parity/README.md](parity/README.md) says where the
snapshot came from and how to refresh it, or how to test against a live iOS checkout instead.

## Releases

Releases are built and signed on a maintainer's machine, never in CI, and uploaded to the
Google Play Console by hand. The first release is submitted and in Google's review, so there
is no public store listing yet. No workflow in this repository holds a signing key, a store
credential or a crash reporting token.

- **versionCode** is `BUILD_NUMBER_OFFSET` (default 4101) plus `git rev-list --count HEAD`, so
  build releases from a full clone, not a shallow one. `app/build.gradle.kts` explains why the
  offset exists.
- **Signing** reads `ANDROID_UPLOAD_KEYSTORE_PATH`, `ANDROID_UPLOAD_KEYSTORE_PASSWORD` and
  `ANDROID_UPLOAD_KEY_ALIAS`: all three, or none for an unsigned build. A partial set fails the
  build.
- **Crash reporting and mapping upload need the Sentry values supplied, because every default
  is empty.** A local release build that should report crashes and upload its ProGuard mapping
  must be given all of these, as Gradle properties (for example in `~/.gradle/gradle.properties`)
  or as environment variables:

  | Gradle property | Environment variable | What it is |
  | --- | --- | --- |
  | `districtSentryDsn` | `DISTRICT_SENTRY_DSN` | The project's DSN, baked into the app. Empty means crash reporting is off. |
  | `districtSentryUrl` | `DISTRICT_SENTRY_URL` | The Sentry host for the organisation's region, e.g. `https://de.sentry.io` for an EU organisation. |
  | `districtSentryOrg` | `DISTRICT_SENTRY_ORG` | The organisation slug the mapping is uploaded to. |
  | `districtSentryProject` | `DISTRICT_SENTRY_PROJECT` | The project slug the mapping is uploaded to. |
  | (none) | `SENTRY_AUTH_TOKEN` | The upload token. Without it the mapping is packaged but not uploaded. |

  A property wins over its environment variable. A build with no DSN says so in one line
  ("Sentry disabled: ...") when Gradle configures the project. A run that reuses the
  configuration cache skips configuration and so does not repeat the line; build a release with
  `--no-configuration-cache` to be sure of seeing it.

```sh
./gradlew :app:bundleRelease    # app/build/outputs/bundle/release/app-release.aab
```

Keep `app/build/outputs/mapping/release/mapping.txt` from the same build. It is not committed,
and without it release stack traces cannot be read.

## What is in this repository

Some values here look like credentials and are not. They are listed so nobody has to guess:

- **Firebase client configuration** in `app/src/main/kotlin/.../push/DistrictFirebase.kt`:
  the project id, sender id, the two Android app ids and the Android API key. This is the
  configuration every Firebase app ships inside its APK (normally via `google-services.json`);
  it identifies the project to Google's client SDKs and grants nothing on its own. It is
  included deliberately, and `DistrictFirebaseTest` pins it. A fork that sends push needs its
  own Firebase project and must replace it.
- **The API base URL** (`https://www.distronode.com`) in `app/build.gradle.kts`.
- **Contract fixtures** in `contracts/`, generated from the server's test suite with fictional
  data. They include LiveKit end-to-end-encryption keys that exist only in that test suite and
  protect nothing; see [SECURITY.md](SECURITY.md).

Nothing here is a secret. If you find something that is, report it as described in
[SECURITY.md](SECURITY.md) rather than in an issue.
